## Verdict

The non-hardware simulation/software gaps previously listed are closed in the
latest evidence set. `nonhardware_pass_fail_metrics.json` reports `PASS` with
`failed=0`.

Closed items:

- D3/D5 vision is driven by Gazebo `/left_camera/image_rect` through
  `aruco_target_node` and `ibvs_controller`; synthetic vision publishers are
  disabled in playback.
- IBVS output is consumed by `visual_servo_gazebo_adapter` and written to
  `/model/left_rm65b/joint_trajectory`.
- D2/D4/D5 force input is fed from Gazebo contact-derived force state into the
  force controller, corrected trajectories are relayed to
  `/model/right_rm65b/joint_trajectory`, and the settling proxy passes.
- D2/D4/D5 include Gazebo Harmonic contact topics with nonzero contact
  messages.
- Gazebo gripper command topics are recorded on all days.
- D4/D5 run the C++ BehaviorTree.CPP runner and record `/weaving/events`.
- D4 teach/replay evidence is generated by the live `/joint_states` recorder:
  `day04/logs/day04_recorded_primitives_from_live_joint_states.yaml`.
- `full_system.launch.py` and `integrated_simulation.launch.py` include camera,
  force, relay, Gazebo bridge, MoveIt, and BT components.
- Runtime MoveIt `/check_state_validity` PlanningScene/FCL sweep executed with
  `service_error_count=0`.

## Runtime Collision Result

| --- | ---: |
| valid samples | 241 |
| invalid/collision samples | 22 |
| service errors | 0 |
| planned trajectory invalid samples | 0 |

The 22 invalid samples are not hidden: they occur at extreme joint3/joint5
fold-back poses where the attached gripper contacts Link1/Link2/Link3 on the
same arm. The D1-D5 planned trajectory samples are valid. This is a sampled
runtime FCL report, not a mathematical proof over the continuous 12-DOF space.
